원격 서비스 차단 검증

GISACLUB · concern: remote-service-control · 2026-11-10

모델·로컬 테스트 통과 프로덕션 배포 승인이나 운영 환경 검증을 뜻하지 않습니다.

판정

서비스가 꺼져 있거나 제어 상태를 읽을 수 없을 때 보호 API와 예약 AI 초안 생성이 시작되지 않도록 수정했습니다. 제공자 응답 뒤 OFF/오류가 관측되면 검토용 콘텐츠 최종화 D1 쓰기를 시작하지 않습니다. 다만 검사를 통과해 이미 시작된 최종화는 OFF 후에도 완료될 수 있습니다. 이 쓰기는 취소 불가한 in-flight 작업으로 모델링했고, OFF 중에는 초안 API로 접근할 수 없습니다. OFF 감지 시 claim 정리를 위해 `failClaim`이 generated content 없이 실패 상태만 기록할 수도 있습니다. 서비스가 다시 켜진 뒤 이미 시작된 콘텐츠 최종화 행이 남아 있지 않다는 보장은 하지 않습니다.

최종 TLA+ 모델에서 `TypeOK`와 7개 안전성 action property가 유지됐습니다(1,345개 생성 / 336개 서로 다른 상태 / 최대 깊이 12). 결함 주입, 보호 응답 도달성, in-flight 콘텐츠 최종화, 차단 claim 상태 경로 도달성 검사는 각각 의도된 반례를 확인했습니다. 마지막 항목의 반례는 정상 상태 경로 증거이지 제품 결함이 아닙니다.

발견 및 수정한 결함 F1

서비스 OFF 우회 — 수정됨. 관리자 블로그 초안 경로가 예외 허용목록에 포함되어 OFF 상태에서도 인증까지 진행했고, Cron은 전역 서비스 상태를 확인하지 않았습니다. 카탈로그 로딩 또는 생성 중 OFF로 바뀌는 경우도 고려하지 않았습니다.

예전 코드의 결함 재현 경로(의도적으로 가드를 제거한 모델):

Init → ControlUnavailable → StartScheduled
위반: 제어 상태를 읽지 못했는데 예약 생성이 loading으로 시작됨

수정 후 허용목록을 명세대로 좁히고, 예약 진입·슬롯 처리·제공자 응답 뒤에 fail-closed 재검사를 추가했습니다. 회귀 테스트는 수정 전 실패, 수정 후 통과했습니다. 별도 MC_boundary.cfg는 콘텐츠 최종화가 시작된 뒤 OFF가 되면 이미 시작된 쓰기가 끝날 수 있음을 의도적 반례로 남깁니다. status-only failClaim 경로는 생성된 본문을 저장하지 않습니다.
