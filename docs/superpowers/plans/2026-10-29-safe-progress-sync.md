# 안전한 학습기록 동기화 실행 계획

**실행 방식:** 현재 작업자가 한 작업자로 진행하며, 각 단계마다 반대 관점으로 A→E 검토한다.

## 순서

1. [x] 소스·호출부·기존 테스트·Worker 계약·저장 정책을 읽고 동기화 범위를 확정한다.
2. [x] `wrongNotes` 원문은 동기화하지 않고 네 개 안전 컬렉션만 확장하는 설계와 수학 단위를 문서화한다.
3. [x] 테스트 우선: Dart snapshot read/merge/계정 분리/tombstone 및 Worker allowlist/검증/병합 테스트를 추가하고 기존 구현에서 실패하는지 확인했다.
4. [x] Flutter snapshot과 로컬 mutation 저장에 timestamp·동기화 예약·수신 병합을 구현했다.
5. [x] Worker snapshot 정규화와 병합 규칙을 동일 계약으로 구현했다.
6. [x] `formal/user-progress-sync`에 슬라이드 max/점수 양자화/등록 삭제를 모델링하고 정상·의도적 결함·sanity 검사를 실행했다.
7. [x] A→E 역검토: 데이터 흐름과 공개 필드 allowlist, 계정 전환, 삭제 경로를 재추적하고 코드 대응표를 갱신했다.
8. [x] Flutter 전체 회귀·전체 앱 분석·Worker 전체 tests와 Wrangler dry-run, TLA+ 정상/결함/도달성 sanity, 정수 경계 검산 결과와 미검증 범위를 핸드오프·분리 체크리스트·저장정책에 기록했다.

## 중단 조건

- 문제/정답/해설/사용자 메모가 새 snapshot 경계에 나타나면 해당 컬렉션 전송을 제외하고 다시 점검한다.
- 운영 배포 또는 계정 설정이 필요해지는 경우에는 로컬 검증을 마친 상태로 경계를 기록하고 배포하지 않는다.
