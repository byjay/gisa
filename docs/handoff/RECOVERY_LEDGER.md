# 실패 원장 (재건)

R60~R86 라운드에서 축적한 원장 35건은 샌드박스 초기화로 소실됐다.
소실된 것을 기억에 의존해 "복원"하면 원본과 다른 물건이 되고, 그것을 복원이라
부르는 것은 거짓 보고다. 그래서 **소실을 사실로 기록하고 여기서 다시 시작한다.**

원장의 목적은 자책이 아니다. 같은 실패를 **물리적으로 불가능하게** 만드는 것이다.
따라서 각 항목은 반드시 「검사」 열에 실행 가능한 방어 장치를 갖는다.
장치 없는 항목은 반성이 아니라 감상이다.

## 이 원장을 쓰는 규칙

1. **항목은 지우지 않는다.** 아래 래칫이 건수 하한을 고정한다.
2. **각 항목은 반드시 실행 가능한 검사를 갖는다.** 검사 없는 항목은 감상이므로 추가 자격이 없다.
3. **검사를 느슨하게 해서 통과시키는 것은 금지한다.** 조이는 방향으로만 갱신한다.
4. **소실된 원장 35건을 기억으로 복원하지 않는다.** 이 파일은 재건이며, 재건임을 명시한다.

현재 건수: **11건 (L1~L11)**. L1~L7 은 위 표에, L8~L11 은 아래 서술형으로 있다.
(형식이 섞인 이유: R60 항목은 표 한 칸에 담기 어려운 분량이라 서술형으로 적었다.
건수를 셀 때는 표 행과 `## L` 헤더를 **둘 다** 세야 한다. 실제로 이번에
`grep -c '^## L'` 만 세어 4건으로 오독했다 — 이것 자체가 L12 급 교훈이다.)

건수 확인 명령(둘을 합산해야 정확하다):

```bash
# 표 행(L1~L7) + 서술형 헤더(L8~) 를 합산
echo $(( $(grep -cE '^\| L[0-9]+ \|' docs/handoff/RECOVERY_LEDGER.md) \
       + $(grep -cE '^## L[0-9]+ ' docs/handoff/RECOVERY_LEDGER.md) ))
```

`survival_check.sh` 가 하한을 고정하지는 않지만,
자기진화 게이트를 재건할 때 이 건수를 래칫 하한으로 삼는다.

## L8 — 내가 만든 검사가 통과 문구를 빈칸으로 찍었다 (R60)

**사실**: `verify_release_ready.sh` ⑤ 단계가 `flutter test` 통과 시
`grep -oE '\+[0-9]+ All tests passed'` 로 통과 개수를 뽑으려 했다.
실제 출력은 `+77: All tests passed!` (콜론 있음) 이라 정규식이 맞지 않았고,
결과는 `✓ ` — **근거 없는 빈 성공**이었다.

**왜 나쁜가**: C10(사용자에게 보이는 숫자는 측정에서만) 위반이다.
"통과했다"고 말하면서 몇 개가 통과했는지는 말하지 못하는 상태였다.
검사기가 자기 출력조차 못 읽으면 그 검사의 통과 보고는 신뢰할 수 없다.

**고침**: 실제 출력을 실측(`tail /tmp/ft.log`)한 뒤 정규식을 맞추고,
**개수를 못 읽으면 통과가 아니라 실패로 처리**하도록 바꿨다.

**검사**: `verify_release_ready.sh` ⑤ 가 `PASSED` 가 비면 `bad` 를 호출한다.

## L9 — 내 검사가 한글 안내문구를 위반으로 오탐했다 (R60)

**사실**: ② 하드코딩 금지 검사가 `grep -rn "ca-app-pub-"` 였다.
그래서 사용자에게 형식을 알려주는 한글 문구
`'앱 ID 형식이 틀립니다 ... (형식: ca-app-pub-숫자16~숫자10)'` 를
"하드코딩된 광고 ID" 로 잡아 출시를 막았다.

**왜 나쁜가**: 오탐하는 검사는 곧 무력화된다. "또 그 오탐이겠지" 하고
사람이 결과를 무시하기 시작하면 진짜 위반도 함께 흘려보낸다.

**고침**: `ca-app-pub-[0-9]{6,}` 로 **실제 숫자를 요구**하도록 좁혔다.
좁히는 것은 완화가 될 수 있으므로 **사보타주로 탐지력이 줄지 않았음을 증명**했다:
`ca-app-pub-1111222233334444/5555666677` 를 심으니 EXIT=1 로 잡았다.

**검사**: 검사를 좁힐 때는 반드시 사보타주로 "여전히 잡는다"를 증명한다.

## L10 — 학습자에게 운영 메뉴가 그대로 보이고 있었다 (R60 실측)

**사실**: `lib/screens/settings_screen.dart` 의 '관리자' 카드('슈퍼 관리자 모드')가
**모든 학습자에게 무조건 노출**되고 있었다. 토큰이 없으면 기능은 막히지만
메뉴 자체는 보였다.

**왜 나쁜가**: 학습자에게 무관한 메뉴는 혼란이고, 운영 화면의 존재와 구조를
그대로 알려주는 셈이다(공격면 확대).

**고침**: `AppConfig.isAdminApp` (컴파일 상수) 가드를 씌웠다. 런타임 스위치가
아니라 `bool.fromEnvironment` 이므로 사용자 앱 바이너리에서는 해당 코드가
tree-shaking 으로 제거된다.

**검사**: `verify_release_ready.sh` ⑥ 가 (a) 기본값이 false 인지
(b) `SuperAdminScreen` 진입점이 가드 안에 있는지 검사한다.
사보타주 S4(기본값 true)로 EXIT=1 확인.

## L11 — 자동 백업 커밋을 내 성과로 착각할 뻔했다 (R60)

**사실**: 라운드 중간에 도구 호출이 중단된 뒤 `git status` 가 깨끗했다.
"내가 커밋했나?" 하고 넘어갈 수 있었지만 측정해보니 `c3a2928 genspark auto-backup`
= **시스템 자동 백업**이 내 미커밋 작업을 커밋한 것이었고,
그 커밋은 **어느 원격에도 없었다**(생존점검 ② 가 EXIT=1 로 잡음).

**왜 나쁜가**: "깨끗한 working tree" 는 "안전하다" 와 다르다.
L1(소실) 이 정확히 이 착각에서 나왔다.

**고침**: `git status` 가 아니라 **원격 도달(ls-remote + merge-base)** 로만
안전을 판정한다. 확인 즉시 푸시했다.

**검사**: `survival_check.sh` ②. 로컬 상태는 증거로 인정하지 않는다.

## L12 — 내 검사가 '모름'을 '없음'으로 단정해 거짓 경보를 냈다 (R60)

**사실**: 라운드 마감 직전 `survival_check.sh` ② 가
"HEAD 27875498 가 어느 원격에도 없다" 고 보고했다. 그런데 나는 직전에
푸시하고 원격 SHA 일치까지 확인했었다. 원인을 측정했더니
`~/.git-credentials` 가 **0바이트로 비워져** `ls-remote` 가
`could not read Username for 'https://github.com'` 로 **인증 실패**한 것이었다.
검사는 `2>/dev/null` 로 그 오류를 버리고, 빈 결과를 곧바로 "없음"으로 단정했다.
재인증 후 측정하니 커밋은 **원격에 정상 존재**(`2787549` 일치)했다.

**왜 나쁜가**: 거짓 경보는 검사를 무력화한다. "또 그거겠지" 하고 사람이
② 를 무시하기 시작하면, 진짜로 백업이 없는 날 소실(L1)을 그대로 반복한다.
또한 "없다"는 사실 주장을 근거 없이 한 것이므로 C1(측정 후 주장) 위반이다.

**고침**: 「조회 실패(unreachable)」와 「조회 성공 + 커밋 없음(absent)」을 분리했다.
조회 실패도 **실패로 처리**하되(안전 우선), 메시지를 "없다는 뜻이 아니다" 로
바꾸고 인증 복구 방법과 `wc -c ~/.git-credentials` 를 함께 안내한다.

**검사**: 사보타주 S5 — 원격에 없는 빈 커밋을 만들면 여전히 EXIT=1 로 차단됨을
확인했다(탐지력 손실 없음). 완화가 아니라 오탐만 제거한 것이다.

**교훈**: 검사기는 세 가지 상태를 구분해야 한다 — **통과 / 위반 / 판정불가**.
'판정불가'를 '위반' 이나 '통과' 중 하나로 접어버리면 그 검사는 거짓말을 한다.

## L13 — 내 검증기가 '해설 37.5%가 무용한' 코퍼스를 '위반 0건'으로 통과시켰다 (R61)

**사실**: `verify_learning_data.py` 는 V0~V7 로 문항 16,653개를 전수 검사해
`✓ 위반 0건 — 해설↔정답 16,653개 대조 완료` 를 냈다. 그런데 해설 본문을
직접 분류해 측정하니 **6,243건(37.5%)** 이 학습에 쓸 수 없는 것이었다.

| 종류 | 건수 |
|---|---|
| 정형문구("이 회차는 공식 해설이 아직 등록되지 않았습니다") | 5,918 |
| 정답번호 머리말뿐(본문 없음) | 278 |
| 그림 안내 문구뿐 | 47 |
| **합계 부채** | **6,243 (37.5%)** |
| 실질 해설 | 10,410 (62.5%) |

**왜 나쁜가**: V5 는 "해설에 적힌 정답번호"만 본다. 즉 **해설이 존재하는지**를
셌을 뿐이고 **해설이 쓸모 있는지**는 한 번도 보지 않았다. 이것이 C13 이 금지한
대리지표(proxy metric)다. 사용자는 "사실검증 통과"라는 말을 듣고 데이터가
완전하다고 믿게 되는데, 실제로는 3문항 중 1문항 이상이 해설 없이 나간다.

**고침**: V8(해설 실질성)을 추가했다. 즉시 6,243건을 위반으로 만들면
"검사를 끄자"는 유혹이 생기므로 **래칫(ratchet)** 으로 설계했다 —
기준선을 `tool/audit/explanation_debt_baseline.txt` 에 못박고, **늘어나면 실패**,
줄어들면 기준선을 자동으로 낮춘다. 출시 게이트 ③ 은 통과해도 부채 수치를
항상 출력해 침묵으로 잊히지 않게 했다.

**검사**: S6(실질해설 1건을 정형문구로 바꿈) → `6,446→6,447 (+1)` 로 **1건 악화도
차단**, EXIT=1. 개선 방향은 기준선이 낮아지고, 낮아진 기준선에서 되돌리면
다시 차단됨을 확인했다(래칫 단방향 증명). 악화 실행이 기준선을 오염시키지
않는 것도 확인했다. 파일 원복은 `sha256sum -c` 로 바이트 동일.

**교훈**: "있다/없다"를 세는 검사는 품질 검사가 아니다. 개수가 아니라
**내용이 목적을 달성하는지**를 검사해야 한다.

## L14 — 결함 개수를 측정하는 내 스크립트가 두 번 연속 틀렸다 (R61)

**사실**: 같은 대상을 세 번 측정했는데 세 번 다 다른 값이 나왔다.

| 회차 | 방법 | 결함 | 해설없음 | 판정 |
|---|---|---|---|---|
| 1차(R60) | 토큰 겹침 ≤1 | 8,647 (51.9%) | 314 | **둘 다 틀림** |
| 2차 | 정확 문자열 | 6,446 (38.7%) | 0 | 정답번호만이 과대(481) |
| 3차(확정) | 머리말 제거 후 본문 길이 | **6,243 (37.5%)** | 0 | 자기검사 9/9 통과 |

**원인 셋**:
1. **JSON 구조 오독** — `exams.json` 은 *회차* 리스트이고 문항은 `exam.questions`
   안에 있다. 표본 스크립트가 회차(193개)를 문항으로 세었다.
2. **한국어 조사** — 문항의 "온수난방**에**" 와 해설의 "온수난방" 이 다른 토큰이
   되어 관련 있는 해설을 '무관'으로 오판했다. 표본 15건을 눈으로 확인해 발견했다.
3. **파이썬 `$` 의 개행 매칭** — `^…[^\n]{0,25}\s*$` 가 본문 있는 해설까지
   '정답번호만' 으로 잡았다(481 → 실제 278). 사보타주 S7 에서만 드러났다.

**왜 나쁜가**: 나는 1차 값 "51.9% / 해설없음 314건" 을 이미 사용자에게 사실로
보고했다. 근거 없는 수치를 사실로 말한 것이므로 C1·C10 위반이다.

**고침**: 판정을 추측(토큰 유사도)에서 확정(정확 문자열 + 머리말 제거 후 본문 길이)
으로 바꿨다. 그리고 `selfcheck_classifier()` 를 검증기에 **영구 내장**해
매 실행마다 판정 로직을 9개 케이스로 먼저 검증하고, 실패하면 데이터 결과를
아예 출력하지 않고 종료한다.

**검사**: S8 — `len(body) < 10` 을 `< 0` 으로 바꿔 아무것도 결함으로 잡지 않게
망가뜨렸더니, 자기검사가 즉시 `✗ V8 판정 로직 자기검사 실패` 로 차단하고
게이트 ③ 도 실패로 전파했다. 원복은 `sha256sum -c` 로 바이트 동일.

**교훈**: 검사기가 낸 숫자는 그 자체로 검증 대상이다. 표본을 눈으로 보지 않고
집계값만 믿으면, 틀린 숫자를 확신을 담아 보고하게 된다. **표본 확인 → 자기검사
내장 → 사보타주** 세 단계를 통과하지 않은 수치는 사용자에게 말하지 않는다.
